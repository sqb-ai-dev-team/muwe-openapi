# Terminal APIs

MUWE terminal APIs follow the same Upay terminal lifecycle: activate once, check in regularly, then sign transaction requests with the active terminal credentials.

## Activate

`POST /terminal/activate`

Registers one terminal device and returns the credentials used for later check-in and transaction requests. Activation requests are signed with `vendor_sn` and `vendor_key`, which are provided offline.

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `app_id` | string | Yes | Vendor application ID registered in MUWE. |
| `code` | string | Yes | Terminal activation code generated by MUWE. |
| `client_sn` | string | No | Terminal identifier in the partner system. Unique under one vendor app. |
| `name` | string | No | Human-readable terminal name. |
| `device_id` | string | Yes | Device identifier, such as IMEI or iOS identifierForVendor. |
| `os_info` | string | No | Operating system information. |
| `sdk_version` | string | No | SDK version used by the terminal. |

Successful activation returns `terminal_sn` and `terminal_key`.

```json
{
  "result_code": "200",
  "biz_response": {
    "terminal_sn": "10298371039",
    "terminal_key": "68d499beda5f72116592f5c527465656"
  }
}
```

Activation is a one-time operation per terminal. Activation codes belong to a store and may have usage-count and expiry limits.

## Check-in

`POST /terminal/checkin`

Refreshes the terminal key. Check-in requests are signed with the current `terminal_sn` and `terminal_key`. After a successful check-in, only the current and previous terminal keys are valid.

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `terminal_sn` | string | Yes | Terminal serial number. |
| `device_id` | string | Yes | Device identifier, such as IMEI or iOS identifierForVendor. |
| `os_info` | string | No | Operating system information. |
| `sdk_version` | string | No | SDK version used by the terminal. |

Successful check-in returns the refreshed `terminal_key`.

```json
{
  "result_code": "200",
  "biz_response": {
    "terminal_sn": "10298371039",
    "terminal_key": "68d499beda5f72116592f5c527465656"
  }
}
```

Terminals should check in at least once per day, preferably before the first transaction.

## Log Upload

`POST /terminal/uploadLog`

Uploads compressed terminal logs for diagnostics. The request is signed with `terminal_sn` and `terminal_key`.

The request body is the terminal log binary stream compressed with gzip.

```json
{
  "result_code": "200",
  "error_code": "SUCCESS",
  "error_message": "ok"
}
```
